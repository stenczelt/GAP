***********************************************
Acceleration of AIMD with On-the-Fly GAP Models
***********************************************

This is the documentation for the ``hybrid-md`` package and framework which
provides acceleration to AIMD, natively in DFT codes through On-the-Fly
building of GAP models. The program currently supports the CASTEP code.


Installation with CASTEP
************************

You will need the following program components:

#. QUIP with GAP
    - MPI-only library module for linking - `libquip.a`` is sufficient
    - OpenMP parallel ``gap_fit`` installation
#. CASTEP: Academic release v22 and above, or development version from git
#. Python installation of ``hybrid-md``


Compiling QUIP/GAP
##################

You will need two builds fo QUIP, one for fitting of the models and one for
evaluation of them form within CASTEP. The reason for this is the different
parallelism supported in these programs.

For fitting, install an OpenMP-only version. It is crucial to *NOT* link MPI
anywhere in this program, due to the design of the external fitting (see below).

Example, on a standard Ubuntu machine:

.. code-block:: bash

    # clone the QUIP repository
    git clone --recursive https://github.com/libAtoms/QUIP.git
    cd QUIP

    # specify the architecture of the build
    export QUIP_ARCH=linux_x86_64_gfortran_openmp

    # configure build - Make sure to say yes to GAP
    make config

    # build: at least the gap_fit program
    make gap_programs

**Note for users of HPC clusters:** Some HPC clusters use MPI-wrappers of
compilers by default, or their maths librarires include MPI calls even when
this code is not compiled wiht MPI. (eg. Archer2 in the UK) Make sure to turn
these off for the first build and turn on for the rest of the compilation
procedure.


The second build will be used for linking to CASTEP, choose an MPI-only arch.
Example:

.. code-block:: bash

    # clone the QUIP repository (or re-use the one from above)
    git clone --recursive https://github.com/libAtoms/QUIP.git
    cd QUIP/

    # remember this directory for configuring CASTEP
    export QUIP_ROOT=$(pwd)

    # specify the architecture of the build
    export QUIP_ARCH=linux_x86_64_gfortran_openmpi

    # configure build - Make sure to say yes to GAP
    make config

    # build: you only need the main static library
    make libquip.a

**GAP version:** Using the same version of QUIP & GAP is recommended for the two
builds, but in case you are updating any, then make sure that the one linked
into CASTEP is the later version, since older versions of GAP cannot evaluate
models generated by newer versions of the program.


**Installation of CASTEP** is documented in the CASTEP source distribution,
the relevant part for this program is inclusion of QUIP, which you can do by
specifying ``QUIP=system`` in the main ``Makefile`` plus providing the
``QUIP_ROOT`` (root directory of QUIP repo) and ``QUIP_ARCH`` (the MPI one).
These can be directly placed into the ``Makefile`` of CASTEP as well to be
exported for easier resume of build or rebuild later.

.. code-block:: makefile

    QUIP=system
    export QUIP_ROOT=...directory from above...
    export QUIP_ARCH=linux_x86_64_gfortran_openmpi


**Python package:** simply install in the package from source, found in the
``GAP/hybrid_md_package/`` directory of this repo.

.. code-block:: bash

    python -m pip install .

This will install a ``hybrid-md`` executable in your associated python
interpreter's path.

Program structures and design
*****************************

The program is intended to be user-accessible and extendable. CASTEP implements
an interfce to external force evaluation codes - includig QUIP/GAP.

Extendability & Development
***************************

Users can extend the framework in multiple ways:

#. Build custom decision making routines: e.g.
    - system specific adaptations
    - utilising confidence estimates of models
    - any exteranl tools working out when the model is extrapolating / could use more data: e.g. sample more when connectivity changes - bond break/form
#. Suport other AIMD codes: There are no specific requirements apart from an internal MD loop being available. Please get in touch with G. Csanyi and T. K. Stenczel for further details.
#. Support for other ML tools - the framework is not depending on GAP
